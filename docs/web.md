# The web app

`web/` is a static site (Vite + TypeScript, no framework) that turns photos
into a Loopy Photo Cart ROM. Everything runs in the browser, and no photo
leaves the user's computer:
- the built site loads only its own files;
- a Content-Security-Policy restricts network requests to its own origin;
- there is no analytics;
- the one fetch is the cartridge template, from the site itself.

## Layout

| Path | What it is |
|---|---|
| `src/core/` | The ROM builder: crop, resample, quantize, grid pages, pack encoder, ROM patcher and validator. Pure TypeScript with no DOM, so the worker and Node scripts share it. |
| `src/core/fonts.gen.ts` | Glyph tables for Home Video Font and Public Pixel Font, generated by `cart/tools/mkwebfonts.py` |
| `src/app/main.ts` | The page: photo list, crop editor, previews, build button |
| `src/app/worker.ts` | Decoding and all processing, off the main thread |
| `public/template/` | The committed cartridge template (`npm run sync-template` refreshes it from `cart/build`) |
| `test/` | Vitest: golden files from the Python reference tools, and a full pipeline test |
| `scripts/demo-rom.ts` | Builds a ROM from JPEGs with the same core, under Node |

## Developing

```
cd web
npm install
npm run dev          # http://localhost:5173
npm test             # unit and golden tests
npm run typecheck
npm run build        # dist/, relative base
```

The Content-Security-Policy is added to production builds only, because the
dev server's hot reload needs inline scripts.

## Keeping it in step with the cartridge

- **Template:** after rebuilding the cart, run `npm run sync-template` and
  commit `public/template/loopy-photo-cart-template.bin`.
- **Pack format:** the TypeScript encoder must stay byte-identical to
  `cart/tools/lpcpack.py`. After changing either, run
  `python cart/tools/mkgolden_web.py` (and `mkgolden.py` for the ROM patcher)
  and `npm test`.
- **Grid page layout or fonts:** `src/core/pages.ts` mirrors
  `cart/tools/lpcimage.py`'s `render_pages`. If the fonts change, run
  `python cart/tools/mkwebfonts.py`; `--check` verifies the committed tables.

## Checking a ROM outside the browser

```
node scripts/demo-rom.ts out.bin ../demo/photos/photo01.jpg ../demo/photos/photo08.jpg
python ../cart/tools/lpcvalidate.py out.bin
```

`lpcvalidate.py` checks a ROM the way the cartridge does, plus the palette
slot rules.

For an end-to-end check of the built site in headless Chromium, run
`npx playwright install chromium` once, then:

```
npm run build
npm run smoke -- out-dir ../demo/photos/photo01.jpg ../demo/photos/photo08.jpg
```

It adds the photos, waits for the previews, builds and downloads a ROM, and
fails on any page error or any request outside the site's own origin.

## Deploying to GitHub Pages

The site is live at <https://loopyphotocart.com>. Pages is set to "GitHub
Actions" with that custom domain in the repository settings, and
`.github/workflows/web.yml` deploys every push to `main` once the tests and
smoke test pass. With an Actions deployment the domain is set in the
settings, not in a CNAME file.

The build uses a relative base (`./`), so `dist/` works from any path. To
publish from GitHub Actions, run `npm ci && npm run build` in `web/` and
upload `web/dist` with `actions/upload-pages-artifact`. Set `BASE_PATH` only
if absolute URLs are needed. Pages on a private repository requires a paid
GitHub plan (docs/PLAN.md §8).

## How photos are processed

1. **Decode:** the worker opens one photo at a time with
   `createImageBitmap(file, { imageOrientation: "from-image" })`. The browser
   applies EXIF rotation and colour management; HEIC opens only where the
   browser supports it (Safari).
2. **Working copy:** the photo is drawn at 1024 px or less on its long side
   into an `OffscreenCanvas`, and the full-size bitmap is closed at once.
3. **Starting crop:** a detail-and-saturation score picks where the
   largest sticker-shaped box sits (`saliency.ts`). Tall photos start as
   portrait stickers.
4. **Render:** the crop box, or the whole photo over a blurred fill, is
   resampled with Lanczos-3 to 256×224 printer dots (224×256 for portrait, then rotated
   90° clockwise).
5. **Quantize:** a deterministic median cut over RGB555 picks colours for
   slots 1–247. Slot 0 is black, and slots 248–255 are the UI colours, which
   photos never use. Floyd–Steinberg dithering is on by default for photos
   and off for grid pages.
6. **Assemble:** 64×60 thumbnails go onto 3×3 grid pages, then the pack is
   built and appended to the template. The ROM is validated before download.
